# V1 — Product Requirements

Audio Recap is a tightly-scoped Claude Code plugin that narrates each
assistant turn so the user can step away from the screen — not just
glance aside — and trust audio to pull them back when there's something
worth acting on. Listening-only: no microphone, no voice input.

## User story

> As a developer who drives Claude Code largely by voice-to-text, I want
> each assistant turn narrated so I can step away from the screen —
> dishes, breakfast, resting — and trust the audio to pull me back the
> moment there's something worth my attention. When I'm ready to reply, I
> push to talk and press Enter.

The pain Audio Recap removes is *babysitting* — without narration you
keep glancing back to check whether Claude is done, and the turn may
have finished minutes ago while you weren't looking. Narration frees
your **attention**, not just your eyes: it lets you fully context-switch
away and trust you'll be pulled back at the right moment. The
one-sentence recap is what makes this work — it answers *is this worth
my attention right now?* without making you parse the whole turn.

Audio Recap is the **output half** of a hands-light loop: it pairs with
a voice-to-text input tool (CC's `/voice`, Whisper, Wispr) and does not
deliver the away-from-screen use case alone. The honest claim is
*attention-free*, not *hands-free* — input stays low-touch (push to
talk, Enter to send), not zero-touch.

Scope: one developer, English, macOS. Audio Recap is a Stop-hook script —
single-shot per turn, no daemon. Multiple concurrent CC sessions are
supported; narration is opt-in per session, so installing the plugin
produces no audio until asked.

## Trigger

Reactive to CC's Stop hook event — invoked when an assistant turn
completes. No daemon, no SDK streaming, no mic-based activation. A plugin
crash or error must not block CC's turn cycle.

## Narration

Each turn produces **at most two segments**, spoken in order. Everything
else — intermediate reasoning, tool-call arguments, tool outputs — stays
silent.

**Segment 1 — Recap.** A one-sentence summary of the turn's actions
(tool calls, files edited, decisions taken) and any error Claude did
*not* recover from.

- Generated by `claude -p --model claude-haiku-4-5` from the turn's
  trace. Default timeout 60 s (`Recap.timeout_s`); past it, the
  rule-based fallback synthesizes a recap directly from the trace ("Edited
  `foo.ts`. Ran tests. Exit 0.") — less natural, always available, never
  silent.
- Target ≤20 words, hard cap 30. Skipped for pure Q&A turns (no tools, no
  edits). Past-tense, first-person.
- **Unrecovered errors appear verbatim** ("tests failed, 3 red"); errors
  Claude recovered from stay silent.

**Segment 2 — Message.** The user-facing text of the turn — answer,
question, or next-step prompt — read verbatim, subject to the speakable
transforms. If the turn ends without a text block (pure tool work),
segment 2 is empty and the recap stands alone.

### Speakable-script transforms

Applied to both segments just before TTS:

| Element           | Behavior                                                     |
| ----------------- | ------------------------------------------------------------ |
| Prose / markdown  | Strip markdown syntax, read text verbatim.                   |
| Inline code       | Read as-is if short (≤3 tokens), else "inline code".         |
| Fenced code block | Announce only: "Code block: N lines, language X." Skip body. |
| Markdown table    | Announce only: "Comparison table: N rows, M columns."        |
| URLs              | Announce domain + link text; never the full URL.             |
| File paths        | Read as a path, not character-by-character.                  |

### Long message handling

A message whose **post-transform** word count exceeds **50 words**
(≈20 s at 150 wpm) is **summarized via `claude -p`**, never truncated.
The summary is not capped — the threshold gates *whether* to summarize,
not how long the result may be. The summarizer prompt biases for ears: prose over
enumeration, takeaways over row-by-row. On summarizer failure the plugin
speaks the full verbatim message — never a truncated form; mid-sentence
cuts never occur.

## Enable / disable

Narration is **off by default** in every CC session. Slash commands:

- **`/audio-recap:on` / `:off`** — enable / disable narration for this
  session.
- **`/audio-recap:status`** — report the current session's state without
  changing it.
- **`/audio-recap:repeat`** — replay the most recent narration audibly.
  State-independent (runs whether narration is on or off): cache hit →
  instant replay; cache miss → generates from the latest assistant turn,
  caches, speaks; empty transcript → a short "Nothing to repeat in this
  session." cue.

State is **per-session** — keyed on CC's `session_id` and the project
working directory, so toggling one CC window does not affect any other.
The state file is created on first `/audio-recap:on`, persists
indefinitely, and survives `claude --continue`. A missing or unreadable
state file reads as **off** (fail-quiet — a broken file never produces
surprise audio). If CC fails to substitute `${CLAUDE_SESSION_ID}`, the
plugin warns to stderr and falls back to a machine-wide state file. When
off, the Stop hook still fires but the plugin exits cleanly — no
`claude -p`, no audio, no side effects.

## Tuning knobs

Per-cwd overrides at `<cwd>/.audio-recap/config.json`, picked up on the
next fire. The recognized keys:

- **`default_enabled`** (default `false`) — start a fresh session in
  this cwd with narration on, without running `/audio-recap:on`.
- **`log_level`** (default `"info"`) — `"trace"` turns on the verbose
  event log (full payloads, `claude -p` prompts/responses, tracebacks).
- **`dry_run`** (default `false`) — run recap + summarization + logging
  but skip the `say` subprocess; for test runners.
- **`tts.trace_speech_log`** (default `false`) — capture a per-fire
  macOS speech-subsystem log excerpt (requires `log_level: trace`).
- **`tts.baseline_wpm`** (default `142`) — reference speaking rate the
  per-fire telemetry compares against.

Other behavior (recap model, summarize threshold, voice, rate) is fixed
at the `audio_recap/config.py` defaults in V1 — not exposed in the
per-cwd file.

## Out of scope for V1

- **Voice input** — no microphone, VAD, or STT. Users reply by typing,
  or with their own OS-level dictation tool into CC's input line.
- **Confirmation / retry / barge-in** — moot without a voice reply.
- **Speak-vs-silent heuristics** — the plugin narrates every Stop event;
  the kill switch is `/audio-recap:off`.
- **Multi-language** — English only (the TTS is multilingual; the
  constraint is scope).
- **Non-macOS platforms** — `say` is macOS-only.
- **Multi-user shared state** — each user's `~/.claude/audio-recap/` is
  independent. Multi-*session* is supported and is the default scope.
