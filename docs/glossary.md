# Glossary

Shared vocabulary used throughout the project and its docs.

### Audio Recap

The user-facing plugin name. Repository slug is `claude-code-audio-recap`,
Python module is `audio_recap`; prose uses "Audio Recap."

### CC plugin

A Claude Code plugin. Audio Recap registers a Stop hook plus the four
`/audio-recap:*` slash commands. Installing makes the hook available;
`/audio-recap:on` activates narration.

### Stop event / Stop hook

The Stop event is the signal CC emits when an assistant turn ends and
control returns to the user. The Stop hook is CC's plugin extension point
that fires on every Stop event; Audio Recap's narration is a single
Stop-hook script that receives the turn's trace, runs to completion, and
exits.

### Reactive trigger

Activation driven by CC's Stop hook rather than by user action. The
plugin does no work except when CC invokes it on turn-end.

### `claude -p` (print mode)

CC's non-interactive mode: given a prompt, it returns a single response
to stdout and exits. Used with `--model claude-haiku-4-5` to generate the
recap and to summarize long messages.

### Recap

The first narration segment: a one-sentence, first-person, past-tense
summary of what Claude did during a turn, plus any unrecovered error.
Generated by `claude -p`; on failure, a rule-based fallback derives it
from the turn trace.

### Message

The second narration segment: the user-facing text of the turn — the
answer, question, or next-step prompt — read verbatim, subject to the
speakable-script transforms. Skipped for turns that end in tool work with
no user-facing text.

### Recap faithfulness

V1's single delivery-integrity concern: the LLM-generated recap could
hallucinate or omit turn content. Bounded (not verified) by the
rule-based fallback derived directly from the trace.

### Narrate mode

Whether the plugin speaks on each Stop event. Default **off**; opt in per
session with `/audio-recap:on`. State is per-session — keyed on CC's
`session_id` and the project working directory — and persists across CC
restarts and `claude --continue`.

### `/audio-recap:*` commands

Four typed slash commands: `/audio-recap:on` and `:off` toggle narration
for the current session, `:status` reports state without changing it, and
`:repeat` replays the most recent narration audibly. `:repeat` is
state-independent — it runs whether narration is on or off — reading the
per-session cache for instant replay, or regenerating from the session
transcript on a cache miss.

### TTS (text-to-speech)

Converts text into spoken audio, applied to both the recap and the
message. V1 ships the macOS `say` backend.
